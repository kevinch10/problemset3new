## 1. My product

- Live address: https://problemset3new.vercel.app/
- Who it is for, and the one job it does for them: A Singapore homebuyer or renter uses the HDB Resale Price Explorer to compare HDB resale transactions by town and flat type and understand how resale prices differ and have changed since 2017.

## 2. My findings

### Finding 1
- Where: https://problemset3new.vercel.app/ — main HDB search/results screen.
- What I did, what I saw: I selected my filters and requested HDB resale information. While the application was waiting for the data, it was not always obvious what was happening or whether I needed to press the button again.
- Which heuristic: 1 — Visibility of System Status.
- Screen or system: Screen. The page itself can show a clearer loading state without needing any new information from the backend.
- Severity, and why: 3 — Major usability problem. The main factor was frequency because this can happen every time a user requests new data, and it may make users think the website is not responding.
- The repair: After a request is submitted, the button should immediately change to something such as "Loading transactions..." and be temporarily disabled until the request finishes.

### Finding 2
- Where: https://problemset3new.vercel.app/ — filters and transaction information.
- What I did, what I saw: I looked at the town, flat type and transaction information as a new visitor. Some information follows the terminology and formatting of the HDB dataset rather than explaining it in language that is immediately meaningful to someone searching for a home.
- Which heuristic: 2 — Match Between the System and the Real World.
- Screen or system: Screen. The interface can translate database values into more natural labels before showing them.
- Severity, and why: 2 — Minor usability problem. The main factor was impact because users can still understand the page, but some labels require additional interpretation.
- The repair: Display user-friendly wording and formatting, such as normal title case for towns and flat types, readable dates, and labels that describe what each value means.

### Finding 3
- Where: https://problemset3new.vercel.app/ — main filters after performing a search.
- What I did, what I saw: I selected a town and flat type and then wanted to start again with a different comparison. I had to manually change the filters rather than having one obvious way to reset the search.
- Which heuristic: 3 — User Control and Freedom.
- Screen or system: Screen. A reset action can be added using information already available on the page.
- Severity, and why: 2 — Minor usability problem. The main factor was persistence because it does not stop the task, but users comparing many areas have to repeatedly undo their selections.
- The repair: Add a visible "Clear filters" or "Reset search" action that returns the page to its original state.

### Finding 4
- Where: https://problemset3new.vercel.app/ — filters, summary information and transaction results.
- What I did, what I saw: I compared the different sections of the page and noticed that information such as prices, dates, headings and controls could follow a more consistent presentation throughout the interface.
- Which heuristic: 4 — Consistency and Standards.
- Screen or system: Screen. The frontend controls how values and interface elements are formatted.
- Severity, and why: 1 — Cosmetic problem. The main factor was impact because the inconsistency does not prevent the user from completing the task, but it makes the product feel less predictable.
- The repair: Use the same currency format, date format, capitalization, spacing and interaction style everywhere on the page.

### Finding 5
- Where: https://problemset3new.vercel.app/ — filter/search controls.
- What I did, what I saw: I tried submitting the search without making all the useful selections and also tried combinations that may return no transactions. The product allows the request to be made before making it clear whether the input is likely to produce a useful answer.
- Which heuristic: 5 — Error Prevention.
- Screen or system: Screen. The application can validate the selections before making the API request.
- Severity, and why: 2 — Minor usability problem. The main factor was frequency because users can easily make an incomplete or unhelpful request, although the mistake is recoverable.
- The repair: Prevent invalid submissions, disable the search button until required choices are made, and explain any required selection beside the relevant control.

### Finding 6
- Where: https://problemset3new.vercel.app/ — town and flat type selection.
- What I did, what I saw: As a first-time visitor, I needed to understand what combinations of town, flat type and other information I could search for. The interface could do more to make available choices and examples immediately visible.
- Which heuristic: 6 — Recognition Rather than Recall.
- Screen or system: Screen. The interface already knows the available categories and can expose them to the user.
- Severity, and why: 2 — Minor usability problem. The main factor was impact because a user can still complete the task, but first-time users have to think more than necessary about what they should enter or select.
- The repair: Use clearly labelled dropdowns, useful default text and examples so users can recognise valid options instead of remembering dataset terminology.

### Finding 7
- Where: https://problemset3new.vercel.app/ — repeated comparisons on the main screen.
- What I did, what I saw: I compared one town and flat type and then tried another comparison. Each new comparison required me to repeat the same selection process, even if I only wanted to change one part of the search.
- Which heuristic: 7 — Flexibility and Efficiency of Use.
- Screen or system: Screen. The current selections can remain available while the user changes only one filter.
- Severity, and why: 2 — Minor usability problem. The main factor was frequency because someone seriously comparing HDB flats is likely to repeat the task many times.
- The repair: Keep existing filters selected when results appear and allow users to change one filter at a time. Frequently used or recent comparisons could also be made easier to repeat.

### Finding 8
- Where: https://problemset3new.vercel.app/ — main results screen, especially on a phone.
- What I did, what I saw: I used the product on a smaller screen and looked for the most important information: the resale prices and transactions. Supporting text and interface elements can compete with the main result and require additional scrolling.
- Which heuristic: 8 — Aesthetic and Minimalist Design.
- Screen or system: Screen. The frontend can change the visual hierarchy without changing the underlying data.
- Severity, and why: 2 — Minor usability problem. The main factor was impact because the information is still available, but the most important answer should be easier to identify immediately.
- The repair: Give the transaction prices and key comparison information the strongest visual priority and reduce or collapse secondary explanations.

### Finding 9
- Where: https://problemset3new.vercel.app/ — results area after a failed or empty request.
- What I did, what I saw: I searched for a case that produced no useful result and considered what would happen if the external data source failed. A generic empty or error state does not clearly tell the visitor whether there are genuinely no transactions, the connection failed, or the upstream service is unavailable.
- Which heuristic: 9 — Help Users Recognize, Diagnose, and Recover from Errors.
- Screen or system: Both screen and system. The backend needs to return distinguishable failure states, while the screen needs to translate those states into understandable messages.
- Severity, and why: 3 — Major usability problem. The main factor was impact because users may incorrectly interpret a technical failure as meaning that no HDB data exists.
- The repair: Show different messages for no matching transactions, an upstream refusal, an unreachable data source and an unexpected application error. Each message should explain what the user can do next.

### Finding 10
- Where: https://problemset3new.vercel.app/ — first visit to the main search screen.
- What I did, what I saw: I opened the product as if I had never seen it before. I could identify the filters, but there was limited help explaining how to make a useful comparison or what the results represented.
- Which heuristic: 10 — Help and Documentation.
- Screen or system: Screen. Short instructions can be added using information the application already has.
- Severity, and why: 2 — Minor usability problem. The main factor was impact because experienced users can work it out, but new visitors may hesitate before making their first search.
- The repair: Add one short instruction near the filters, for example: "Choose a town and flat type to compare resale transactions recorded since 2017." A short explanation of what the price information represents should also appear near the results.

## 3. My predictions

1. The three findings I expect my groupmates to raise, and the severity I expect them to give each:

   - **Finding 1 — Visibility of System Status: Severity 3.** I expect this to be raised because every groupmate will experience a data request and can immediately notice whether the website clearly communicates that it is loading.
   - **Finding 8 — Aesthetic and Minimalist Design: Severity 2.** I expect this to be especially noticeable on a phone because the main information has to compete for limited screen space.
   - **Finding 9 — Error Recognition and Recovery: Severity 3.** I expect this to be raised when groupmates deliberately break the product because different failures need to tell the user what actually went wrong and what they should do next.

2. The heuristic I think my product breaks worst: **9 — Help Users Recognize, Diagnose, and Recover from Errors.** The product depends on an external HDB data source, so an unsuccessful request can mean several different things. If these situations look the same to the user, they cannot tell whether their search was wrong, no transactions exist, or the external service failed.

3. The finding that would show my own evaluation was wrong: A groupmate identifying a **severity 3 or 4 problem with the normal search and comparison flow that I did not record at all** would show that I was too familiar with my own product. For example, if several first-time users cannot understand what they need to select or cannot work out how to get their first result without help, I would have underestimated the usability problem because I already knew how the interface was supposed to work.
